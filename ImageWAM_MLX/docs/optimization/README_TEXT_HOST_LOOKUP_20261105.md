# 文本缓存命中路径：CPU 直接查键候选

状态：候选与自动测试脚本已实现，尚未完成整网测试；默认推理代码未修改。

当前 runtime 先 mx.array(ids)，TextCache.__call__ 再 np.asarray(ids) 生成键。候选使用现有 CPU token 数组直接查键，仅 miss 时才构建 MLX token 数组。可以消除命中路径上的数组转换；不能直接断言每次转换都有独立物理复制或同步，实际收益需测量。

实验继承当前指令更新、完整 token 键、LRU容量和字节上限，保留动态文本。测试包含6个完整推理数值对照（更换指令、改变图像和状态、长文本）、80组随机交替端到端计时和500组查键微测。与现有缓存命中路径比较，不与无缓存路径混淆。

首次运行发现 Pi05 新的模型测试后，只终止了本轮实验。已按此前授权启动15秒周期空闲监控，连续3次空闲才开始；运行期间发现其他模型任务会只中止自身并创建新记录目录重试。
