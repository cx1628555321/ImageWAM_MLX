# 门控与激活拼接融合（2026-11-04）

## 范围与基准

在上一轮自适应 Split-K 路径上，把动作单流块中的 concatenate([attention, SiLU(a)*b]) 合为一个 Metal 内核，尝试省去中间门控输出及一次拼接读取。涉及20个单流块，每次请求10步。三图预处理、文本长度、权重、量化配置和去噪步数不变。没有增加全权重反量化。

基线是上一轮 adaptive Split-K，不是生产 speed 或 PyTorch。生产代码和上一轮实验入口未修改。

环境：M5 Pro，15 CPU核/16 GPU核，24GiB统一内存；macOS27.2，Python3.12.13，MLX0.32.4。

## 三种实现

1. 首版：一维索引，直接 sigmoid=1/(1+exp(-x))。与MLX公式及精度行为不同，产生差异，淘汰。
2. 公式对齐版：按已安装 MLX unary_ops.h 的 Sigmoid 实现，使用 precise::exp(abs(x)) 和符号分支，保留 BF16 舍入。
3. 二维版：公式不变，直接以线程 x/y/z 对应列/行/批次，去掉逐元素除法、取模计算。读取真实 strides，不要求MLP切片连续。

## 算子与端到端验证

随机算子探针包含 strided MLP 输入、horizon 1/8/14/16/32/64。公式对齐版及二维版在所有这些探针中逐值一致；二维版增加 max_abs==0 断言。首版最大差0.25（随机激活输出，不是最终动作误差），不能使用首版替换原逻辑。

每版各100对完整请求，AB/BA交替，双方各首次及3次预热后计时。真实三图、39token文本、16×14动作、10步；每次重新执行完整前向。计时包含CPU输出，不包含模型加载、磁盘读取及保存。模块分析另做3次同步前向。首次调用共享编译缓存，不能比较冷启动收益。

## 结论

本轮未将候选合入默认路径。若完整对照没有正向收益，减少一个中间张量或内核并不构成有效优化。原图已通过 mx.compile 编译，自定义融合改变了访存、向量化和调度方式；没有GPU时间线，本轮不能把退化精确归因到其中某一项。

保留代码和负结果，后续优先通过可用的算子级计时/内存记录定位主要开销，避免继续仅按算子数量猜测收益。可以考虑在量化投影的输入读取中直接消费两段激活，但需防止多个输出块重复计算门控；该方案本轮未实现，不计入收益。
