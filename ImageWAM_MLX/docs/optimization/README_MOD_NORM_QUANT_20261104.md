# 2026-11-04：LayerNorm / 调制 / INT8 量化边界融合

本轮以已经包含门控量化融合的正式 `--profile speed` 为对照，新增两个实验实现并扫描八种线程配置。没有改写模型权重、配置或 accuracy 路径。候选仅位于 `experiments/mod_quant_20261104/`，未加入默认推理。

## 实现与范围

- `candidate.py`：保留 MLX 原生 LayerNorm，融合 BF16 scale+1、乘法、shift、行最大值、INT8 量化和分块布局写入；256 线程。
- `candidate128.py`：同样计算，128 线程。
- `candidate_norm.py`：进一步把 LayerNorm 均值、平方均值、归一化融合进同一个内核；256 线程。
- 作用于视觉 single-block 0–18 的 linear1 输入，继承当前 gate/concat/prepacked INT8 实现；最后一层的 compact KV 路径保留原实现。
- 输入 token 行数动态决定，未固定文本长度。没有缓存实际请求输入。三图、状态、文本、初始噪声均来自原测试输入。
- 三步融合的方差使用 E[x²]−E[x]²，会改变浮点归约及舍入；对消误差也可能降低稳定性。不是与原生 LayerNorm 普遍等价的替换。

## 完整推理配对测试

M5 Pro（15 CPU / 16 GPU，24 GiB 统一内存）、MLX 0.32.4，`MLX_MAX_OPS_PER_BUFFER=256`。三组分别预热 5 次、随机顺序配对 200 次，计时包含 predict 调用及前后 GPU 同步。相同模型权重共享，避免双份权重引起交换。95% 区间是 10,000 次配对 bootstrap，不代表消除了系统负载影响。

| 候选 | 同期正式 speed 平均 ms | 候选平均 ms | 节省 ms | 节省的 95% 区间 ms |
|---|---:|---:|---:|---:|
| 调制+量化，256 线程 | 213.688 | 213.917 | -0.229 | [-4.175, 3.780] |
| LayerNorm+调制+量化，256 线程 | 220.614 | 228.581 | -7.967 | [-12.495, -3.311] |
| 调制+量化，128 线程 | 224.541 | 221.386 | 3.154 | [-2.349, 8.745] |

不同时间段不能相减作为优化收益。当前结果未证明精确融合稳定提速；三步融合在本轮完整推理中明显变慢。

## 数值验证

每组均测试了已有的 51 个 RoboTwin/文本长度案例，并保存动作及归一化输出。

- 两种仅融合调制和量化的布局：51/51 动作及归一化输出逐值一致。
- 三步融合：51/51 输出有限；相对当前 speed 的最大动作绝对误差 0.0169596672，最大单案例动作 RMSE 0.0035392034，最大归一化动作绝对误差 0.0234375。标准样本最大动作误差 0.0160012245。
- 上述是相对已有 speed 的新增误差，不是相对 PyTorch 的总误差；未测试机器人任务成功率。
- `norm.log` 沿用脚本的 `warmup exact` 标签并不表示该候选精确；实际误差以 `initial error`、保存数组及 `norm/validation.json` 为准。

## 微基准及解释

`micro.py` 使用随机 BF16 [328,3072] 输入；包含 LayerNorm 至量化输出的完整局部子图。每种布局预热 10 次、随机交错测量 200 次；Python 调用和同步开销也包含在内。它只用于筛选，不代替真实输入的完整推理。

| 实现 | 平均 ms | 中位数 ms |
|---|---:|---:|
| 当前原生子图 | 0.208472 | 0.168563 |
| mod128 | 0.185017 | 0.159375 |
| mod256 | 0.191259 | 0.161000 |
| mod512 | 0.189234 | 0.160625 |
| mod1024 | 0.211888 | 0.173250 |
| norm128 | 0.179992 | 0.152958 |
| norm256 | 0.170172 | 0.149396 |
| norm512 | 0.179190 | 0.151626 |
| norm1024 | 0.201292 | 0.166167 |

局部收益未转化为可确认的端到端收益。融合减少中间张量，但加入多轮归约、线程组屏障及活跃寄存器；整个计算图的调度也会改变。这些是待 profiler 验证的原因，当前数据不能确定具体哪个因素主导。尤其随机微基准几乎一致，真实模型的 norm 融合却产生误差，不能以随机输入精确替代真实模型验证。
