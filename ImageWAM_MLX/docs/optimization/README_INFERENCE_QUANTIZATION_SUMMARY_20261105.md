更新：2026-11-05。汇总已有实测记录，本次没有重新跑全部历史版本。远端：`/Users/qklj/work/cx/ImageWAM_MLX`。

## 阅读口径

设备为 M5 Pro，15 CPU 核、16 GPU 核、24 GiB 统一内存；macOS 27.2、Python 3.12.13、MLX 0.32.4。主要基准输入为 RoboTwin 三图、状态、39-token 指令、H16、14维动作。端到端从已解码输入到 CPU 反归一化动作，不含加载、磁盘读取、保存或仿真。

**只有同轮旧/新对照才能用于计算某项优化收益。不同日期/负载下的绝对耗时仅用于列示版本，不能相减归因，也不能把每项收益累加。** ms越低越好；“降低%”指延迟降低，不是吞吐提高百分比。表内数值使用报告精度，末位可能有舍入差。

当前 API/infer 的 `--profile speed` 默认单条文本缓存；benchmark 默认 `--text-cache-size 0`。不指定 profile 仍为 accuracy。

## 二、当前各模块真实权重与激活类型

|模块|权重/存储|主要计算激活、累加和输出|当前状态|
|---|---|---|---|
|Qwen文本编码|BF16|BF16为主，必要统计/位置计算保留FP32|未采用整体低比特量化；相同文本缓存最终特征|
|VAE图像编码|BF16|BF16卷积及浮点归一化|fast BF16路径，不是INT8卷积|
|视觉专家38个single-block linear1/linear2|源自W4 affine group64，加载时预展开为常驻INT8|在线INT8激活，INT8×INT8→INT32，缩放后BF16|计算主体可称W8A8；不能称全图W4A8|
|其余视觉层、条件投影等|BF16为主|BF16/FP32|未统一量化|
|动作专家65个合格Linear|W1 affine group64，packed权重及浮点scale/bias|BF16激活；适用大K层Split-K为FP32部分和，再BF16输出|W1A16；不是INT1激活推理|
|KV、attention、残差、调度|浮点|BF16/FP32|没有将全部KV/softmax切换成INT8|

依据：`imagewam_mlx/quantized.py`、`runtime.py`、`action_kernel.py` 与以下量化报告。SPEED_POLICY中的visual=bf16是构造起点，runtime随后将38层替换为staged/prepacked INT8，不能只读策略字典就称视觉全BF16。

“有效”指已采纳的端到端路径；组合实验未消融时明确标注，不把组合收益冒充纯位宽收益。

|动作W1 Split-K＋门控/残差融合|240.778→226.693|14.085|5.85%|优化已有W1内核，没有进一步降位宽；[报告](README_BEST_SPEED_20261104.md)|
|视觉W4来源的staged INT8计算＋buffer256|260.167→230.060|约30.106|11.57%|正式ABBA组合收益；[报告](README_RUNTIME_TUNING_20261104.md)|

W1首次启用的纯量化独立收益，没有在所引用最终报告中可靠分离；只报告上表组合实测，不能虚构“W1单独降低多少”。同理，不提供没有控制实验支持的W1/W4/W8通用速度排序。

## 六、精度与启动成本

accuracy作为精度对照，与PyTorch BF16仍可能存在跨框架浮点差异。speed采用激进W1，历史标准样本相对参考最大动作绝对差约1.808、RMSE约0.518；这不是当前所有用例的统一误差界。视觉staged INT8当时相对旧speed另有最大约0.022613的新增动作差。没有完成RoboTwin闭环成功率验证。

后续“逐值一致”均说明相对对应speed基线没有新增数值差异，不代表量化模型与PyTorch无损。4步相对10步speed的51用例平均逐样本RMSE为0.382030、最大绝对差1.392112。

缓存更新入口本轮完整7场景/正式CLI与无缓存对照逐值一致。最新全模型试验加载3.939秒、首次文本准备5.079秒；独立CLI准备2.793秒、首次完整请求611.617 ms、完整启动6.681秒。首次含编译等成本且波动明显，不能使用169.379 ms代表启动延迟。

## 七、统一复测命令

在远端项目根目录执行，每个输出目录必须是新目录：

```bash
cd /Users/qklj/work/cx/ImageWAM_MLX
# 选择下表参数；此示例为当前缓存命中的10步路径
.venv/bin/python scripts/benchmark.py \
  --profile speed --text-cache-size 1 --steps 10 \
  --reference examples/robotwin_ep0_frame0 \
  --warmup 10 --iterations 100 --profile-iterations 3 \
  --output "records/version_compare_$(date +%Y%m%d_%H%M%S)"
```

|要复测的配置|替换参数|参考均值 ms|
|---|---|---:|
|accuracy|`--profile accuracy --text-cache-size 0 --steps 10`|281.650，历史|
|speed无缓存|`--profile speed --text-cache-size 0 --steps 10`|193.399，最新同轮|
|speed缓存命中|`--profile speed --text-cache-size 1 --steps 10`|169.379，最新同轮|
|speed无缓存4步|`--profile speed --text-cache-size 0 --steps 4`|159.888，旧内核历史|
|speed缓存4步|`--profile speed --text-cache-size 1 --steps 4`|136.390，旧内核历史；原测容量8，同一指令命中|

上述统一命令用于新复测，其预热/次数不冒充各历史记录原始协议。PyTorch和早期MLX版本需使用其原记录/快照；不要用当前CLI倒退参数就声称复现了所有历史实现。

实际输入推理使用scripts/infer.py；当前speed自动准备文本并开启单条缓存，连续服务请复用模型实例。缓存关闭必须显式传0。
