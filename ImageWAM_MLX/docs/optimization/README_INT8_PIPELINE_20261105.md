# 视觉 INT8 双缓冲流水实验（2026-11-05）

结论：完成适配与真实三图测试，但收益未通过独立进程复核，**不合入默认**。当前 speed 继续使用上一轮尾块版本。没有改动生产 Python、模型权重或输入语义。

## 实现与边界

实验位于 `experiments/int8_pipeline_20261105/`，基线包含已固化的 INT8 尾块优化。两个候选分别对全部 38 个视觉 INT8 线性层启用双缓冲，或仅对输出维度 3072 的 linear2 启用，其余层沿用当前正式内核。

预装第一块权重，每个 K 循环将下一块写入另一个 threadgroup 缓冲，再计算当前块；末尾统一同步并交换缓冲角色。单循环同步从两次减少到一次，另外保留初始化同步。线程组权重缓冲约 5 KiB → 10 KiB。保留整数累加顺序、缩放、BF16 舍入、64 行激活布局和尾块策略，没有完整权重反量化。

这是软件流水安排，不是已由 GPU 时间线证明加载/计算重叠。额外共享内存可能影响驻留率，但目前没有计数器证据证明它是退化的唯一原因。

## 测量

M5 Pro / MLX 0.32.4，真实 RoboTwin 三图、39-token 文本、H16、10 步；在线编码、不缓存特征，计时到 CPU 动作输出。与上一轮相同的硬件及端到端边界，模型加载/首次单独记录。

|方案|端到端均值 ms|相对基线节省 ms|配对 bootstrap 95% 区间 ms|
|---|---:|---:|---|
|当前正式基线|196.834|0|—|

### 第一轮独立进程

顺序：基线/全部/局部/局部/全部/基线，各预热 10 次、稳态 100 次，随后模块诊断 5 次。合并结果：

|方案|均值 ms|P95 ms|两个进程均值 ms|
|---|---:|---:|---|
|基线|202.627|208.722|206.265 / 198.988|
|全部双缓冲|202.953|208.214|204.232 / 201.673|
|仅 linear2|202.130|209.442|206.843 / 197.417|

局部候选均值仅省 0.496 ms，首轮略慢、反向轮次较快，无法仅凭合并平均值确认稳定收益。

### 追加独立 ABBA 复核

各进程同样预热 10 次、稳态 100 次，所有样本保留：

|顺序|方案|均值 ms|进程 CPU 时间 ms/请求|
|---|---|---:|---:|
|A1|基线|205.180|100.308|
|B1|局部候选|201.923|41.934|
|B2|局部候选|207.435|102.331|
|A2|基线|197.492|38.202|

基线合并 **201.336 ms**，局部候选 **204.679 ms**，候选慢 **3.343 ms**。P95 为 206.395 → 209.058 ms。因此不采用双缓冲，不把同进程 195.620 ms 宣称为新的部署性能。

CPU 时间为全进程各线程累计量，不是单线程耗时或 GPU 时间。两种实现都出现快慢状态，尚未确定根因。测试期间曾观察到另一个 Pi0.5 MLX Python 进程；只能确认存在资源竞争可能，不能据此追溯解释每个样本。本轮没有停止其他任务。

全量候选一个进程首次前向约 41.122 秒、加载约 18.197 秒，另行记录，没有混入稳态均值；无法仅凭这次现象区分编译、内存或调度成本。不能将该候选视为已适合部署。

## 精度与审计

* 完整、局部候选各通过 51 组真实输入的 action/normalized 逐值一致性检查。
* 完整候选另通过 4 组动态边界：39 tokens/H1/1步、39/H8/3步、189/H16/10步、39/H64/11步。
* 两轮共 10 个独立进程的保存输出与同轮基线逐值一致。
* `audit.json` 对照上一轮正式 CLI 源码哈希，确认生产 Python 未改动。
* 这里的一致性相对于量化 speed，不代表相对于 PyTorch/accuracy 无损或已验证闭环成功率。
