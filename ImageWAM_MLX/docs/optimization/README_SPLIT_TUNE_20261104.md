# Split-K 并行度与 NAX 布局调优（2026-11-04）

## 范围

在上一轮 W1 Split-K 门控残差融合版基础上，适配目标线程组数量与矩阵块布局。没有改变模型权重、三图预处理、文本 token、去噪步数；没有增加整层权重反量化。生产默认代码和上一轮实验均未修改。

基准是上一轮 Split-K 融合版（target=512，BM32/BN64/WM2/WN2），不是生产 speed，也不是 PyTorch。不能将本轮数值与其他系统状态下的历史速度直接相减。

M5 Pro / 15 CPU 核 / 16 GPU 核 / 24 GiB 统一内存，macOS 27.2，Python 3.12.13，MLX 0.32.4。

100 对 AB/BA 交替；共用模型权重，双方各首次运行及3次预热后计时。每次重新计算三图编码、文本、视觉前缀与动作，不复用跨请求特征。包括 CPU 动作输出，不包括模型加载、磁盘解码和输出保存。首次调用共享编译缓存，不能用它推导冷启动收益。

## 结论

本轮端到端配对呈正向收益，但优势有限且更长动作序列可能存在数值差异。已增加 adaptive 布局以消除长动作长度上的新增差异，未替换默认生产路径或上一轮入口。

下一步应优先减少动作层的激活拼接或归约读写，并先做同形状算子探针；不继续盲目增加 Split-K 分块数。

## 推荐 adaptive 路径的最终验证

51 组样本（31–79 token 长度覆盖及真实图像案例）全部与上一版 Split-K 逐值一致，max abs=0.0。额外 horizon=[1, 8, 14, 15, 16, 32, 64] 也逐值一致。长文本 193 token 的 horizon16 配对检查也一致。

adaptive 对 eligible Linear 在动作长度14–16时选择16/64/1/2布局，长度>16保留32/64/2/2；长度<=13沿用原官方路径。文本长度不参与此路由，无截断或固定文本要求。默认16步动作的内核与上述100对compact确认相同。

推荐命令已使用 --layout adaptive；--layout compact 仍可用于诊断，但长动作序列会改变数值。此处无新增误差指相对上一版量化融合路径，不代表与BF16/PyTorch一致。
