# Split-K 归约展开专项（2026-11-05）

## 结果与决定

继续在现有 speed 路径上测试 GPU 内部优化。本轮实现三种归约内核候选；保持原 W1 矩阵乘、Split-K 分区、FP32 累加顺序、BF16 舍入与残差语义。**未确认达到默认切换门槛的新收益，正式推理代码未修改。**

设备仍为 M5 Pro、24 GiB 统一内存、MLX 0.32.4。三图、10 步、无跨请求特征缓存、动态文本。性能使用标准三图与固定初始噪声，输入到 CPU 动作输出；不含模型加载、文件读写。未使用缓存、减少步数或减少输入长度来加速。

## 为什么测试这里

动作分支每次推理调用 200 次 W1 Split-K 矩阵乘及后续归约/残差内核。代表性真实投影为 `(M,N,K)=(16,1024,7168)`。以现有 target512、tile16×64 配置，K 分成 28 份，FP32 partial 大小为 1,835,008 字节，至少产生约 3.5 MiB 的逻辑写入+读取。此数是逻辑流量，不是实测 DRAM 流量，缓存可能吸收其中一部分。

过去已测试减少分区和向量化归约；本轮聚焦显式展开 Split 循环和线程映射组合。由于保持分区与中间缓冲格式不变，**本轮并未减少 partial 数量或字节数**，只能尝试减少循环控制和改善调度。

|候选|归约方式|线程组|
|---|---|---:|
|baseline|现有循环，每线程一输出|256|
|u1_256|显式展开循环，每线程一输出|256|
|u1_128|显式展开循环，每线程一输出|128|
|u4_128|显式展开循环，每线程四输出|128|

非整除形状回退现有实现；小动作长度仍走现有非 Split-K 路径，没有固定文本长度。

## 实测性能

完整推理每模式预热 5 次，60 轮随机顺序交替，每模式 60 请求，总计 240 次计时。所有模式使用相同 workspace_step 编译包装，避免编译入口差异。它是完整 predict 的受控对比，不是另外执行正式 CLI 的独立进程复核。

|候选|完整推理均值 ms|P95 ms|比同期基线节省 ms|
|---|---:|---:|---:|
|baseline|201.216|202.976|—|
|u1_256|200.866|202.769|0.350|
|u1_128|201.083|203.223|0.133|
|u4_128|201.214|203.106|0.002|

最快候选仅约 **0.17%**，低于既定至少 max(2 ms,1%) 的默认切换门槛，因此未继续宣称正式部署收益，未替换默认。不将本次基线与上轮 192.752 ms 跨时段相减归因。

实际捕获投影、显式张量参数、mx.compile、每候选预热15次、200轮随机交替、每次 eval 同步的局部测试：

|baseline|u1_256|u1_128|u4_128|
|---:|---:|---:|---:|
|0.284070 ms|0.285266 ms|0.283472 ms|0.285498 ms|

局部测量也未显示明显收益。这是投影+归约的同步 host wall，包含调度，不是纯 GPU kernel 时间。最早捕获闭包形式的 micro 只保留为诊断记录 `micro_captured_diagnostic.json`，报告使用显式参数重测后的 `micro.json`。

## 精度与复现

标准计时请求每次均比较 action/normalized，均逐值一致。另测动作长度 H=1、H=64，以及 H=16 的长文本，检查回退和不同形状。51 个既有 RoboTwin 样本/文本用例的基线与三个候选输出单独保存在 `records/split_reduce_20261105/validation/`，**51 个用例 × 3 个候选，共 153 组比较全部逐值一致，max_abs = 0；动态检查也全部通过。**

比较对象是当前量化 speed，不是原 PyTorch/BF16，也没有重新评估机器人任务成功率。

## 后续方向

本轮证据降低了继续微调归约循环的优先级。更有价值的下一步是分析 Split-K 主矩阵乘的分区内部加载、屏障和计算流水线；若尝试消除 partial 缓冲，则必须同时处理跨分区求和次序和 GPU 全局同步问题，不能直接把两个 kernel 合并就认为等价。先在真实热点形状上测量，再要求完整推理验证。
